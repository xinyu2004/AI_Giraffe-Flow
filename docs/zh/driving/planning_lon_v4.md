## 1. 为什么叫规控

和 A* 同一类感觉：**先有计划，再沿计划走**。不是这一拍猜 ACC 还是 AEB。

计划要能画出来、能看懂：一条**规划路径** + **分段速度**（哪一段要减速、哪一段要提速、要不要换道）。看得到未来加减速的力度，也看得到变道意图。本拍油门刹车只是在执行这份计划。

场景变了，先改计划，再改踩踏。邻道意图、后车插、进出隧道，都是场景证据，没有哪一条等于整套逻辑。

## 2. 三层

```text
场景（环境 + 我能看多远、多确信）
    → 计划（路径 + 分段速度；时域由视野动态定，基准约 10 s）
        → 执行（本拍 thr / brk / steer）
```

| 层 | 做什么 |
|----|--------|
| **场景** | 正常人会用来改走法的一切：车、车道、空档、灯、挡视线、隧道致盲、车道增减、环视后的后车……以及**这次计划允许看多远** |
| **计划** | 在可见、可信的范围内搜/排出一条路（类 A*：有走廊、有代价、有一段未来），输出路径折线 + 各段速度/加减速度 |
| **执行** | 跟踪计划在「现在」的速度与曲率；安全减速度始终在，饱和只是计划已经要求全力减 |

禁止把三层压成本拍互斥档。日志里的 cruise/acc/aeb 只是执行输出的标签，不回写状态。

---

## 3. 计划时域：基准 10 s，不是写死 10 s

希望**默认能看到大约 10 s 的规划**（BEV 上就是那条带速度的路）。10 s 是 **cal 基准 `T_base`**，不是物理常数。

实际时域/距离由「我这拍能信的视野」收：

```text
D_see = min( D_fov_conf,  D_vr,  D_occlusion,  D_cal_cap )
T_plan = min( T_base,  D_see / max(v, v_floor) )
D_plan = min( D_see,  v * T_plan 的夹紧 )
```

| 量 | 含义 | 从哪来 |
|----|------|--------|
| `T_base` | 基准思考时间，量级 10 s | cal |
| `D_fov_conf` | 相机 FOV、清晰度、探测置信能支撑的距离 | cal 表 + 感知质量（不是写死米数） |
| `D_vr` | 车道可视距离（LH VR_End 等） | 感知 |
| `D_occlusion` | 前方大车等挡住的有效视线 | 场景（大车尾部之后打折或截断） |
| `D_cal_cap` | 演示/算力上限 | cal |

视野好、没挡：计划就接近 10 s，能看出后面几秒要不要变道、要不要收油。  
进隧道口致盲、大车挡死、线模糊：计划**缩短**，人也会改成「先看清再想远」。缩短的是计划长度，不是改成无计划的分档刹车。

## 4. 计划长什么样（要能看见）

一份计划至少：

- **路径**：车道坐标系或 ego 下的折线（可变道：先沿本车道再偏入邻道，像搜出来的走廊，不是只有居中点）
- **分段速度**：若干段，每段 `v` 或 `v + a`，能读出「这一段在收、这一段在抬、这一段在让插入」
- **时域/空间长度**：本拍的 `T_plan` / `D_plan`

和现在只有 xy、纵向另跟模式名不同：路径和速度是**同一份计划**。BEV 应能画出这条路和速度分段，才叫「有计划的开车」。

第一刀搜索可以很笨（沿当前车道削速度）；结构必须已经是「路径 + 分段速度 + 动态视野」，才能往上加变道代价、后车、隧道，而不必推翻。

## 5. 场景（开放集合，正常人逻辑）

都是修订**同一份计划**的证据。表是例子，不是 OEM 清单，也不是做完才算 v4。

| 证据 | 对计划 |
|------|--------|
| 前方空、视线也空 | 分段速度向巡航抬 |
| 本车道前车靠近/在减速 | 前方段降速，预备刹车写在剖面上 |
| 前车打灯或横向趋势：要出 / 要插 | 填空或让插入（抬速或压速），不要等贴脸 |
| 邻道更慢、没有往里趋势 | 保持相对速度通过；剖面上留刹车余量 |
| 它外侧还有车在挤 | 提高「它可能跟着插」的代价，提前压速或改走廊 |
| 车道将变少/汇入（预判） | 提前选走廊、提前降速，不要到锥形端再抢 |
| 车道变多 | 计划仍走合理走廊，不是无故甩方向 |
| 进出隧道、出光致盲 | 缩短 `D_see` / 压 `T_plan`，速度段保守 |
| 前方大车挡视线 | `D_occlusion` 截断或降置信，计划不要画过看不见的地方还当空路 |
| 环视后：后车加速、要变道超车/加塞 | 改走廊或提前让/稳住，不要只看 CIPV |
| 极近仍在轨迹上 | 该段减速度饱和（标签可叫 aeb） |

今天没有的输入（灯、环视后车、隧道标志、清晰度）是**场景缺口**。钩子留在「改计划 / 改 D_see」，输入来了接同一处，不新开档。

## 6. 执行（内环）

```text
v_plan(0),  κ_plan(0)   ← 计划在此刻的速度与路径
a_req                   ← 近处相对运动的安全减速度（多目标取严）
throttle, brake, steer  ← 跟计划；a_req 优先
```

饱和不是进入 AEB 控制器。禁止 latch。`d_stop` 只标定全力减的尺度。

## 7. 相对 v3

| v3 | v4 |
|----|-----|
| 本拍四档 | 视野内搜一份未来（类 A* 的「有路、有速」）再执行 |

## 8. 落地顺序

1. **计划对象 + 能画**：路径点带分段速度；`T_plan` 先用 `T_base` 与 VR 夹紧（FOV/遮挡表可后挂）。
2. **执行跟剖面**：去掉互斥档。
3. **场景往计划上加**：空档、插入、灯、大车挡视、隧道、车道增减、后车……都改走廊或速度段。

第一刀走廊可以仍是本车道，但输出必须已经是「一段未来的路 + 分段速度」，不能再是本拍 classify。

**做法：** 只动 `.m` + Host 一次 `m_plan_tick`；变道搜索（刀 4）未上之前只出 `allow_lc` 旗标，不扫第二走廊。C 等效果认可后再 generate。

## 9. 非目标

量产 AEB/LKA 法规、HLB/FS、Host 后再套一层刹/舵壳。  
不要求第一刀就上完整环视 A* 和换道；要求**形态**已经是有视野的计划，和正常人「看多远想多远、路上能看出下一步」一致。
