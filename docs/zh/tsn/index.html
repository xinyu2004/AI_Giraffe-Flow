Access / Trunk

交换机口决定帧进和帧出时带不带标签。Giraffe 是端点。自己插入 PCP 和 VID 时，对面那一口按 trunk 收发，优先级才能留给下一跳的门控。页 2 还没有这个字段。

门控表

这就是页 2「时间 / 门控」里的 AdminControlList。每一行是时长，加上 8 位 GateStates。没改页 2 时，tsync.yaml 里不会出现 network。

页 2 保存的是 Admin 表。把表写进网卡、再读回正在跑的 Oper 表，页面上还没有。运行时目前只读 backend 和 pretend_synchronized。

流过滤与监管

按 PCP 匹配，先看最大帧长，再看令牌桶。示意固定为 PCP 5、最大帧长 1500、CIR 1000 kbit/s、CBS 2000 字节。页 2 没添加行时不写入 stream_filters 和 flow_meters。

CNC 和 AVTP

名字它是什么Giraffe 里怎么放
CNC Central Network Controller，IEEE 802.1Qcc 里的集中网络控制器。它掌握拓扑和每条流的周期，算出每一台交换机端口的门控表并下发。 不做成页面。页 2 写下的 stream_filters 和 flow_meters 是交给交换机入口的意图，本机不执行。
CUC Centralized User Configuration。发送端和接收端把流的周期、大小登记给它，再由它告诉 CNC。 不做成页面。
AVTP Audio Video Transport Protocol，IEEE 1722。样本直接装在以太网帧里，EtherType 0x22F0，不经 IP。AVB 用它传声音和图像。 协议栈不实现。图像走共享内存，跨 ECU 的服务走 SOME/IP。历史动画里保留它，用来说明 TSN 的来路。
