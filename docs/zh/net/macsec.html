MACsec

用 0x88E5 把以太网帧逐跳套起来。每一跳有自己的密钥。交换机要读的 VLAN 标签留在套子外面。

一跳里有什么

IEEE 802.1AE。这一跳上的保护分成三层，换密钥时新的安全关联先准备好，再切 AN，免得这一跳断掉。

成员是什么
连接关联 CA已经达成一致的两端
安全通道 SC其中一个方向
安全关联 SA通道上的一把密钥。用关联号 AN 区分，AN 只有 0 到 3

帧上用的密钥是 SAK。SAK 从哪里来，是 MKA（IEEE 802.1X 里的协定）的事：成员先有一把连接关联密钥 CAK，MKA 用它在这一跳上推出当前的 SAK，并约定从哪个包序号开始用。算法和密钥的存放在 AI Fortress Auto 的 HSM 说明里，这页不写推导。

端口在模型里分成两面。不受控的一面在保护建立之前也能收发，MKA 自己的报文走这里。受控的一面只放已经套上 MACsec、并且校验通过的帧。交换机若只是透明转发、自己不是这一跳的端点，它解不开，也看不到 VLAN 以内的以太类型。

在哪一层

数据链路层的蓝框里。和 802.1Q 一样，是插进帧的标签，不是 IP 以上的层。有 VLAN 时，次序跟总图一致：目的 MAC、源 MAC、0x8100 和 TCI、0x88E5 和 SecTAG、原来的 EtherType、载荷、ICV、FCS。VLAN 在外面，交换机不用解密就能看到 VLAN 号，也能按 PCP 选队列。

报文

三条类型各留各的。0x8100 是 VLAN，0x88E5 是 MACsec，最里面仍是原来的 EtherType，IPv4 就是 0x0800，gPTP 就是 0x88F7。没有 VLAN 时，0x8100 和 TCI 不出现。

目的 MAC明文6 字节。这一跳谁接收
源 MAC明文6 字节。这一跳谁发出
0x8100明文有 VLAN 才有
TCI明文PCP · DEI · VID
0x88E5明文MACsec
SecTAG明文下表逐条列出
EtherType密文原来的类型。只做完整性时仍是明文
载荷密文里面的包。只做完整性时仍是明文
ICV明文完整性校验
FCS明文CRC-32 · 4 字节
SecTAG 里作用
TCI版本、这一帧有没有加密、SCI 带没带、是不是单收端。E 表示加密，C 表示改过的文本要做校验
AN两比特，指出 0 到 3 里的哪一条安全关联
SL短长度。帧不长时写出载荷有多长，长帧则另有约定
PN32 位包序号。接收方用它防重放，序号用尽就要切到下一条 SA
SCI可选，8 字节：源 MAC 再加端口号。一条链路上有多个发送者时用来分清是哪条通道

ICV 在 FCS 前面。FCS 仍是以太网自己的 CRC-32，盖住的是已经套好的这一帧。对端先看 FCS，再看 ICV。只做完整性、不加密时，载荷仍是明文，ICV 照样在。

对时帧

gPTP 的帧常常不进这条加密关联，走不受控的那一面。加解密会改变驻留时间，门控若按保护之前的时刻计算，时序就偏了。所以对时帧常常留在 0x88E5 外面，EtherType 仍直接是 0x88F7。哪些帧进关联，是这一跳的策略，不是 gPTP 头里的一个标志。

不做什么

  • 不是端到端。过一台交换机就要解开再套上，下一跳是另一把 SAK。字节流的两端是 TLS，主机到主机的 IP 是 IPsec。
  • 不吃掉原来的 EtherType。0x88E5 套在外面。
  • 0x88E3 不是 MACsec。那个类型号不属于 802.1AE。
  • 不保护没进这条关联的帧。gPTP 常常就在外面。门控和驻留时间仍看 TSN。
  • 交换机自己不是端点时，不能假设它会把套子拆掉再转发。套子停在这一跳的两个端口之间。
