SOME/IP

控制器在以太网上按服务通信：调用方法，或订阅事件，不必先排好一整张信号表。

服务、方法和事件

BMW 提出，后来收进 AUTOSAR。一个服务有 16 位服务号。同一服务可以有多个实例，实例号也是 16 位。主版本必须一致才算同一个接口；次版本用来表示向后能接上的修订。

方法是一次调用。请求要返回，消息类型是 REQUEST。不等返回，是 REQUEST_NO_RETURN，调用方发完就走。事件是服务方在值变化或按周期送出的通知，消息类型是 NOTIFICATION。方法号的最高位区分这两类：0 是方法，1 是事件。几个事件收成一个事件组，订阅按组来，不按单个事件来。

消息类型值谁发给谁
REQUEST0x00客户端调用，等响应
REQUEST_NO_RETURN0x01客户端调用，不等
NOTIFICATION0x02服务端送出事件
RESPONSE0x80服务端对请求的正常返回
ERROR0x81服务端拒绝或出错

带 TP 的类型是上面这几个再加分段标志，用来把一条大报文拆进多个 UDP 包。见下面的分段。

发现

SOME/IP-SD 负责“谁提供服务、事件送到哪”。它自己仍是一条 SOME/IP：服务号 0xFFFF，方法号 0x8100，消息类型是通知。规范把 SD 报文的端口定成 SD_PORT，默认 UDP 30490，源端口和目的端口都用它。组播地址由 SD_MULTICAST_IP 配置，同一网段里要一致。能合并的条目放进同一条 SD，少发几次。

三条阶段

每个服务实例或事件组，发出条目之前都走过这三段。初始等待的时间在最小值和最大值之间随机取，避免上电时所有节点同时开口。

阶段做什么
初始等待链路起来、服务也准备好之后先等一段随机时间，再发第一条
重复第一条发出后，按基数间隔重复，次数有上限，间隔逐次加倍
主阶段服务端按周期继续 Offer。客户端不再周期性地 Find

条目

条目分两类，每条 16 字节。服务条目谈服务实例，事件组条目谈订阅。生存时间 TTL 以秒计。0xFFFFFF 表示一直有效，直到对方明确停止。TTL 写成 0 就是停止：停 Offer，或停订阅。订阅确认的 TTL 写成 0，就是拒绝这次订阅。

条目类型值作用
FindService0x00打听谁提供这个服务
OfferService0x01宣布自己提供这个实例。TTL 为 0 即停止提供
SubscribeEventgroup0x06订阅一个事件组。TTL 为 0 即退订
SubscribeEventgroupAck0x07确认订上了。TTL 为 0 即拒绝

Find 的实例号可以写成 0xFFFF，表示这个服务的任一实例都行。主版本必须对上。次版本写成 0xFFFFFFFF 表示任意次版本，写成别的值就是能接受的最低次版本。多个实例同时 Offer 时，条目里可以带优先级和权重：优先级数字小的先被选，同一优先级再按权重分。

SD 头里有重启标志和单播标志。会话号从 1 递增。会话号绕回、重启标志变化，别人把这台机器当成重启，已经订过的事件组要重新订阅。

选项

条目指向选项。选项里才是地址。

选项里面有什么
IPv4 端点地址、UDP 或 TCP、端口。服务从这里进，事件也从这里出
IPv4 组播事件要送去的组播地址和端口
配置若干键值，给这个服务带额外参数
负载均衡优先级和权重

订阅若要求 TCP，客户端得先把 TCP 连上。服务端发现该连的 TCP 没有，可以拒绝这次订阅。客户端则检查这条连接，必要时重连。

在哪一层

应用层。方法调用和事件在车上常见走 UDP。总图上可以把传输改成 TCP，只有这条可靠字节流上才能再套 TLS。SecOC 和 E2E 加在这条 PDU 上，不另开一层。

TCP 是字节流，粘包之后靠 SOME/IP 头里的长度切开。流一旦错位，用魔术字重新对齐：客户端的消息号是 0xFFFF0000，服务端是 0xFFFF8000。

报文

头在载荷前面。服务号和方法号合成消息号。长度从请求号算到报文末尾，不包含消息号和长度自己。请求号由客户号和会话号合成，用来把响应配回某一次调用。

返回码

响应和错误报文用返回码说明结果。通知的返回码是 0x00。

返回码值含义
E_OK0x00成功
E_NOT_OK0x01没有更细的原因
E_UNKNOWN_SERVICE0x02不认识这个服务
E_UNKNOWN_METHOD0x03服务在，方法不在
E_NOT_READY0x04服务还没准备好
E_NOT_REACHABLE0x05现在够不着
E_TIMEOUT0x06内部超时
E_WRONG_PROTOCOL_VERSION0x07协议版本不对
E_WRONG_INTERFACE_VERSION0x08接口版本不对
E_MALFORMED_MESSAGE0x09报文不完整或对不上
E_WRONG_MESSAGE_TYPE0x0a消息类型不该出现在这里

序列化

基本类型默认按网络字节序，高字节在前。结构体按成员顺序排。动态数组和字符串前面有长度。经典 SOME/IP 字符串的长度是 32 位，把字节序标记和结尾的 0 都算进去。AUTOSAR 的序列化器还能改长度字段的宽度和哪些字段带长度，两边的配置必须是同一份。

UDP 上的分段

一条报文塞不进一个 UDP 包时用 SOME/IP-TP。消息类型带上分段标志，SOME/IP 头后面多 4 字节：偏移以 16 字节为单位，另有一个“后面还有段”的标志。接收方按偏移拼回，拼齐才交给上面的服务。

不做什么

  • 不代替事先排好的 CAN 信号表。服务、方法和事件是另一套编址。
  • SD 只发现服务和事件组，不运送服务自己的参数。
  • 车上常见走 UDP。UDP 不是可靠字节流，套不上 TLS。
  • 不保护链路，也不保护整份 IP。链路是 MACsec，IP 是 IPsec。
