DDS

多个节点按主题共享同一类数据。时效、历史和可靠性都写在 QoS 里，发现也按这套 QoS 决定谁和谁接得上。

主题和实例

OMG 的数据分发服务。一个域里，发布方是 DataWriter，订阅方是 DataReader。两边的主题名和类型名对上，样本才有地方去。类型里可以指定键。键的每一个取值是一个实例：同一主题上，车速是一个实例，每个雷达目标可以是各自的实例。历史深度是按实例留的，不是把整个主题揉成一条队列。

发现

发现分两步，都走 RTPS 的内置端点。SPDP 让参与者知道谁在这个域里：周期宣布自己，并带上租约，租约到期就认为对方走了。SEDP 再交换各自的 DataWriter 和 DataReader，包括它们的主题、类型和 QoS。对不上的 QoS 不会匹配，数据送不过去。联调时最常见的沉默就是这里：进程都在，主题名也一样，可靠性或持久性一边要、一边不给。

对照 SOME/IP-SD：SD 按服务号、实例号和事件组做 Offer、Find、Subscribe；DDS 按域、主题名、类型和 QoS 做匹配，没有服务号这一层。

也有不跑 SPDP、端点事先写死的部署。那样就没有组播宣布，地址和 QoS 都在配置里。

域和端口

同一个域号的参与者才互相发现。RTPS 用域号和参与者号算出 UDP 端口。默认常数：端口基数 PB = 7400，域增益 DG = 250，参与者增益 PG = 2，偏移 d0 = 0、d1 = 10、d2 = 1、d3 = 11。发现组播地址的默认是 239.255.0.1。

端口算法域 0、参与者 0
发现组播PB + DG × 域 + d07400
用户组播PB + DG × 域 + d27401
发现单播PB + DG × 域 + d1 + PG × 参与者7410
用户单播PB + DG × 域 + d3 + PG × 参与者7411

同一台机器上第二个参与者是 7412 和 7413。实现可以改这些常数。两边改得不一样，就互相看不见。

QoS

QoS 是这条数据怎么送、留多久、迟到算不算故障。有的策略必须两边匹配，叫请求/提供：读者的要求不能高过写者提供的。有的只约束本地队列，不参与匹配。

策略常用取值车上用来做什么
ReliabilityBEST_EFFORT 或 RELIABLE雷达点、视频常常尽力而为。控制指令和状态常常要可靠：写者发 HEARTBEAT，读者用 ACKNACK 要缺的样本
DurabilityVOLATILE 或 TRANSIENT_LOCALVOLATILE 不给晚加入的人补历史。TRANSIENT_LOCAL 把写者内存里的历史补给后上线的读者，晚加入也能拿到最后一帧。TRANSIENT 和 PERSISTENT 还要持久化服务，车上少用
HistoryKEEP_LAST 加深度，或 KEEP_ALL传感器常用深度 1，只留最新。指令有时深度大于 1，避免把还没读的覆盖掉。这是本地队列，不参与匹配
Resource Limits样本数、实例数、每实例样本数给上面的历史封顶。封满之后新样本会被丢掉或堵住写者。本地策略
Deadline一段时长两个样本之间最多隔多久。写者提供的周期必须不长于读者要求的。超时是通知，不是把样本改掉
LivelinessAUTOMATIC，或按参与者、按主题手动对方还在不在。AUTOMATIC 靠任何写操作续租。手动则要显式断言。写者的断言方式必须满足读者的要求，租约也不能更长
Lifespan一段时长样本过了这段时间就过期，读者不该再把它当新的。本地策略
OwnershipSHARED 或 EXCLUSIVE多个写者写同一实例时，SHARED 都收。EXCLUSIVE 只认强度最高的那个写者，用来做冗余切换。两边必须同一种
Ownership Strength一个整数只在 EXCLUSIVE 下有意义。强度高的成为属主，它停了，次高的接上
Time Based Filter最小间隔读者主动丢弃来得太密的样本。本地策略
Latency Budget一段时长希望多快送到。写者给的时延必须不大于读者要的。它是提示，不是定时器
Transport Priority一个整数发送优先级的提示。标准不规定它等于哪个 VLAN PCP，有的实现会拿它去选队列
Destination Order按收到的时间，或按源时间戳多个写者时，按源时间戳可以不把晚到、但时间更早的样本当成更新
Partition一组名字同一域里再分逻辑组。分区字符串对不上，端点不匹配

匹配时常见的高低关系：可靠性上，读者要 RELIABLE 就只能配 RELIABLE 的写者，读者要 BEST_EFFORT 则两种写者都能配。持久性从低到高是 VOLATILE、TRANSIENT_LOCAL、TRANSIENT、PERSISTENT，写者提供的不能低于读者要的。Deadline 和延迟预算是写者答应的时间不能比读者松。所有权必须两边一样。

在哪一层

应用层是 DDS。节点之间的报文是 RTPS，常见走 UDP。总图上可以把传输改成 TCP。保护是 DDS-Security，做在 RTPS 上，分成三块插件：认证、访问控制、加密。总图不给 DDS 勾 SecOC 和 E2E。默认 UDP 没有可靠字节流，套不上 TLS。DDS-Security 也不靠 TLS。

报文

RTPS 头带协议标识 RTPS、版本、厂商和 GUID 前缀。后面是子消息。

子消息作用
DATA运一个样本，或运发现用的内置数据
DATA_FRAG样本太大，拆成片
HEARTBEAT写者告诉读者：我的序号从哪到哪。可靠传输靠它推动确认
ACKNACK读者回答还缺哪些序号。这是可靠性确认，不是 IP 头里的 ECN
GAP这些序号可以跳过，不必再要
NACK_FRAG / HEARTBEAT_FRAG对分片做同样的缺片和心跳
INFO_TS / INFO_DST给后面的子消息带时间戳，或指明要送给谁

可靠传输的一轮是：写者发 DATA，再发 HEARTBEAT；读者发现缺口就回 ACKNACK；写者把缺的序号再送一次。尽力而为则没有这一轮。

不做什么

  • 不按服务号和方法号调用。那是 SOME/IP。
  • ACKNACK 是可靠传输的确认，不是 IP 的 ECN。
  • SecOC 和 E2E 不加在 DDS 上。认证和加密是 DDS-Security 的插件。
  • QoS 对不上时协议不会报一条“错误返回码”。端点就是不匹配，读者收不到样本。
