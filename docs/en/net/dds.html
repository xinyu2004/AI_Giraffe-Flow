DDS

Nodes share one kind of data by topic. Timing, history, and reliability are written in QoS, and discovery uses that same QoS to decide who matches whom.

Topic and instance

The OMG data-distribution service. Inside one domain, what is published is a sample, and what is subscribed is a sample. The topic, the instance, and this one value each do a different job.

MemberWhat it does
TopicThe name and type of one kind of data. The two sides match before a sample has anywhere to go
InstanceOne value of the key. On the same topic, vehicle speed is one instance, and each radar target can be its own. History is kept per instance
SampleOne value a writer sends
Writer / readerA DataWriter publishes. A DataReader subscribes. This is publish and subscribe, not one call

Discovery

Discovery has two steps, both on RTPS built-in endpoints. SPDP is the Simple Participant Discovery Protocol. SEDP is the Simple Endpoint Discovery Protocol. Blue and orange only mark direction. Both sides do the same thing: SPDP announces a participant on a cycle, and a peer is treated as gone when the lease expires; SEDP then exchanges each side’s DataWriters and DataReaders. QoS that does not match does not pair, and the data is not delivered. The usual silence during bring-up is here: both processes are up, the topic name matches, and one side requests reliability or durability that the other does not offer.

Participant AParticipant B

  1. SPDPAnnounce this participant in the domain, with a lease

  2. SPDPThe other side announces itself too

  3. SEDPThis side’s writers, readers, topics, types, and QoS

  4. SEDPThe other side’s writers, readers, and QoS. No match means no data

The two steps

StepRole
SPDPSimple Participant Discovery Protocol. Announce this participant in the domain on a cycle, with a lease. When the lease expires, others treat the participant as gone. The announcement uses the discovery ports below
SEDPSimple Endpoint Discovery Protocol. Exchange writers, readers, topics, types, and QoS. A mismatch does not pair, and the data is not delivered

Compared with SOME/IP-SD: SD offers, finds, and subscribes by service ID, instance ID, and eventgroup. DDS matches by domain, topic name, type, and QoS. There is no service ID.

A deployment can also skip SPDP and fix the endpoints in configuration. Then there is no multicast announcement. Addresses and QoS are in the configuration.

Domain and ports

Only participants with the same domain ID discover each other. RTPS computes UDP ports from the domain ID and the participant ID. The default constants are port base PB = 7400, domain gain DG = 250, participant gain PG = 2, and offsets d0 = 0, d1 = 10, d2 = 1, d3 = 11. The default discovery multicast address is 239.255.0.1.

PortFormulaDomain 0, participant 0
Discovery multicastPB + DG × domain + d07400
User multicastPB + DG × domain + d27401
Discovery unicastPB + DG × domain + d1 + PG × participant7410
User unicastPB + DG × domain + d3 + PG × participant7411

A second participant on the same machine uses 7412 and 7413. An implementation may change these constants. If the two sides change them differently, they cannot see each other.

QoS

QoS says how this data is sent, how long it is kept, and whether lateness counts as a fault. Some policies must match on both sides. That is requested and offered: the reader’s request cannot be stricter than what the writer offers. Others only bound a local queue and do not take part in matching.

PolicyUsual valuesWhat it is for in a vehicle
ReliabilityBEST_EFFORT or RELIABLERadar points and video are often best effort. Control commands and state are often reliable: the writer sends HEARTBEAT, and the reader uses ACKNACK to ask for missing samples
DurabilityVOLATILE or TRANSIENT_LOCALVOLATILE does not fill history for a late joiner. TRANSIENT_LOCAL gives a late reader the history still in the writer’s memory, so a late joiner can still get the last sample. TRANSIENT and PERSISTENT also need a persistence service and are rarely used in a vehicle
HistoryKEEP_LAST with a depth, or KEEP_ALLSensors often use depth 1 and keep only the latest. A command sometimes uses a depth above 1 so an unread sample is not overwritten. This is a local queue and does not take part in matching
Resource LimitsSample count, instance count, samples per instanceA cap on the history above. Once full, a new sample is dropped or the writer blocks. A local policy
DeadlineA durationThe longest gap allowed between two samples. The period the writer offers must be no longer than the reader requests. A miss is a notification. It does not rewrite the sample
LivelinessAUTOMATIC, or manual by participant or by topicWhether the other side is still there. AUTOMATIC renews the lease on any write. Manual requires an explicit assertion. The writer’s assertion must meet the reader’s request, and the lease must not be longer
LifespanA durationA sample expires after this time. A reader should not treat it as new. A local policy
OwnershipSHARED or EXCLUSIVEWhen several writers write one instance, SHARED accepts all of them. EXCLUSIVE accepts only the writer with the highest strength, which is how a redundant takeover is done. Both sides must use the same kind
Ownership StrengthAn integerMeaningful only under EXCLUSIVE. The higher strength becomes the owner. When it stops, the next one takes over
Time Based FilterA minimum separationThe reader drops samples that arrive too close together. A local policy
Latency BudgetA durationHow soon delivery is wanted. The latency the writer offers must be no greater than the reader asks. It is a hint, not a timer
Transport PriorityAn integerA hint for send priority. The standard does not equate it with a VLAN PCP. Some implementations use it to pick a queue
Destination OrderBy reception time, or by source timestampWith several writers, source timestamp can keep a late sample with an earlier timestamp from counting as an update
PartitionA set of namesA further logical group inside one domain. Endpoints do not match when the partition strings do not

The usual order at match time: for reliability, a reader that requests RELIABLE matches only a RELIABLE writer, while a reader that requests BEST_EFFORT matches either writer. Durability from low to high is VOLATILE, TRANSIENT_LOCAL, TRANSIENT, PERSISTENT, and the writer’s offer cannot be lower than the reader’s request. Deadline and latency budget cannot be looser than the reader asked. Ownership must be the same on both sides.

Where it sits

The application layer is DDS. The packet between nodes is RTPS, commonly over UDP. The overview can switch the transport to TCP. Protection is DDS-Security, done on RTPS, in three plugins: authentication, access control, and cryptography. The overview does not offer SecOC or E2E on DDS. The default UDP path has no reliable byte stream, so TLS does not fit. DDS-Security does not depend on TLS either.

Packet

The RTPS header carries the protocol mark RTPS, a version, a vendor ID, and a GUID prefix. Submessages follow.

SubmessageRole
DATACarries one sample, or built-in data used for discovery
DATA_FRAGThe sample is too large and is split into fragments
HEARTBEATThe writer tells the reader the range of sequence numbers. Reliable delivery uses it to push acknowledgement
ACKNACKThe reader reports which sequence numbers are still missing. This is the reliability acknowledgement, not ECN in the IP header
GAPThese sequence numbers may be skipped. Do not ask for them again
NACK_FRAG / HEARTBEAT_FRAGThe same missing-fragment and heartbeat exchange for fragments
INFO_TS / INFO_DSTA timestamp for the following submessages, or a statement of who they are for

One reliable round is: the writer sends DATA, then HEARTBEAT; the reader replies ACKNACK when it sees a gap; the writer sends the missing sequence numbers again. Best effort has no such round.

What it does not do

  • It does not call by service ID and method ID. That is SOME/IP.
  • ACKNACK is the acknowledgement of reliable delivery, not IP ECN.
  • SecOC and E2E are not added on DDS. Authentication and encryption are DDS-Security plugins.
  • When QoS does not match, the protocol does not return an error code. The endpoints simply do not match, and the reader receives no samples.
