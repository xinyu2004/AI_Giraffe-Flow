DoIP

Diagnostic messages between a tester and an ECU move from CAN onto Ethernet. Once the connection is up, the payload is UDS.

How one diagnostic session connects

ISO 13400. The tester finds the vehicle, then opens TCP, then activates routing, and only then can send UDS. The order cannot be reversed. Blue to the right is what the tester sends. Orange to the left is what the vehicle returns.

TesterVehicle

  1. Vehicle identification requestUDPType 0x0001, port 13400

  2. Vehicle announcementUDPType 0x0004. VIN, EID, GID, and logical address. Also the identification response; the vehicle may send it on its own

  3. Connect · TCP 13400, or 3496 when TLS is used. Activation is due in about 2 seconds

  4. Routing activation requestTCPType 0x0005. Register the tester’s source address

  5. 0x0006TCPResponse code. Success is 0x10

  6. 0x8001TCPThis packet’s payload is a source address, a target address, then UDS

  7. 0x8002TCPThis packet was accepted. 0x8003 rejects it. This is not the UDS positive response

  8. A later 0x8001TCPThe UDS positive response. The service ID is the request ID plus 0x40

  9. TesterPresentTCPStill inside 0x8001. About 5 minutes with no packet drops the connection

If the same source address is already on another TCP connection, the entity first runs an alive check (0x0007 / 0x0008). While the old connection is still alive, the new activation is rejected.

Routing-activation result

This table lists only the response code inside 0x0006. It does not explain 0x8001, and these are not UDS service IDs. The request carries the tester’s source address and an activation type. The default type is 0x00. WWH-OBD, used for regulated diagnostics, is 0x01. Common response codes:

Response codeMeaning
0x10Activation succeeded
0x11One more confirmation is required before it counts as success
0x00This source address is unknown
0x01The TCP sockets are full
0x02This connection already has a different source address
0x03This source address is already on another connection
0x04Authentication is still missing
0x06This activation type is not supported
0x07Cleartext is rejected. TLS is required

On 0x07, close the cleartext TCP on 13400, connect to 3496, finish the TLS handshake, and send routing activation again. The DoIP header is inside the TLS record.

Where it sits

Application layer. Diagnostic messages are fixed on TCP. That path is already a reliable byte stream, so TLS can be selected on the overview from the start. The vehicle identification request and the announcement use UDP 13400. The overview does not put SecOC or E2E on DoIP.

Packet

The header has four fields: protocol version, the inverse of the version, payload type, and payload length. The inverse is the version byte bitwise inverted, so a non-DoIP packet can be rejected early. The table below is that two-byte type. How one row’s payload is split is written in the section after the table, not in the table itself.

Version1 byte. 0x02 is 2012, 0x03 is 2019. The vehicle identification request and the announcement use 0xFF
Inverse1 byte. The version with each bit flipped: 0x02 pairs with 0xFD, 0x03 with 0xFC, 0xFF with 0x00
Type2 bytes. Listed row by row in the table below
Length4 bytes. How many payload bytes follow. The 8-byte header is not counted

0x8001 and its acknowledgement

Opening 0x8001 from the type table, the payload is still this same packet, after the DoIP header, in three fields. UDS is the last field, not a following DoIP message. The source is the tester. The target is one ECU, or a functional address that a group of ECUs all hear. The numbers are assigned by the manufacturer. The range commonly used by an external test device is set aside in the specification.

Source2 bytes. The tester’s logical address
Target2 bytes. One ECU, or a functional address heard by a group of ECUs
UDSService IDs in the table below

0x8002 only says the DoIP entity accepted the packet and may forward it. The UDS positive response is a later 0x8001, with the service ID equal to the request ID plus 0x40. 0x8003 drops the packet. Common reasons:

CodeMeaning

0x03Unknown target address
0x04The diagnostic message is too large
0x05Not enough memory
0x06The target cannot be reached
0x07The network to use is unknown

What it does not do

  • It does not specify the parameter layout of every UDS service. That is ISO 14229.
  • 0x8002 is not the UDS positive response. The positive response is still a 0x8001.
  • The address is a DoIP logical address, not a CAN identifier.
  • The overview does not put SecOC or E2E on DoIP. To protect this TCP connection, use TLS or IPsec.
