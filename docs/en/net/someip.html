AutoEth

SOME/IP

Controllers talk by service over Ethernet: call a method, subscribe to an event, or read and write a field that has a current value. A fixed signal list is not required first.

Method, event, field

BMW designed it, and AUTOSAR later adopted it. A service has a 16-bit service ID. One service can have several instances, and the instance ID is 16 bits too. The major version must match for it to be the same interface. The minor version marks a revision that older clients can still use. A service has three kinds of members.

MemberWhat it doesOn the wire
MethodOne call. Wait for the return, or send and leaveREQUEST or REQUEST_NO_RETURN. The high bit of the method ID is 0
EventOne notification. The server tells whoever has subscribedNOTIFICATION. The high bit of the method ID is 1. Subscribe by eventgroup first
FieldA property with a current value. Get, set, and notify-on-change may each be left outGet and set are methods. The notifier is an event. After a notifier is subscribed, the server sends the current value first

A method is a remote call. An event is publish and subscribe: there is no call paired with a return. A field getter and setter use a method message. The notifier uses an event message. There is no fourth message type. An eventgroup subscribes ordinary events and field notifiers together.

Message typeValueWho sends it
REQUEST0x00The client calls and waits for a response
REQUEST_NO_RETURN0x01The client calls and does not wait
NOTIFICATION0x02The server sends an event
RESPONSE0x80The server’s normal return to a request
ERROR0x81The server rejects the call or reports an error

The TP types are these same types plus a segmentation flag, used to split one large message across several UDP packets. See segmentation below.

Discovery

SOME/IP-SD answers “who offers this service, and where do events go”. It is still one SOME/IP message: service ID 0xFFFF, method ID 0x8100, message type notification. The specification names the SD port SD_PORT. The default is UDP 30490, used as both source and destination. The multicast address comes from SD_MULTICAST_IP and must be the same on that segment. Entries that can be combined go in one SD message, so fewer packets are sent.

Finding a service and then subscribing to an event is a round trip. Blue to the right is the client. Orange to the left is the server.

ClientServer

  1. FindServiceAsk who offers this service

  2. OfferServiceAnnounce that this instance is offered

  3. SubscribeEventgroupSubscribe to one eventgroup

  4. SubscribeEventgroupAckThe subscription is accepted. TTL 0 rejects it

Three phases

Each service instance or eventgroup passes these three phases before an entry is sent. The wait belongs to that one side. The initial delay is chosen at random between a minimum and a maximum, so nodes do not all speak at once when power comes on.

  1. Initial waitAfter the link is up and the service is ready, wait a random time, then send the first entry
  2. RepetitionAfter the first entry, repeat on a base interval, up to a maximum count, and double the interval each time
  3. MainThe server keeps offering on a cycle. The client no longer sends Find on a cycle

Entries

Entries come in two kinds, 16 bytes each. A service entry is about a service instance. An eventgroup entry is about a subscription. TTL is in seconds. 0xFFFFFF means it stays valid until the other side stops it. TTL 0 means stop: stop the offer, or stop the subscription. A subscribe ack with TTL 0 rejects that subscription.

EntryTypeRole
FindService0x00Ask who offers this service
OfferService0x01Announce that this instance is offered. TTL 0 stops the offer
SubscribeEventgroup0x06Subscribe to one eventgroup. TTL 0 unsubscribes
SubscribeEventgroupAck0x07The subscription is accepted. TTL 0 rejects it

A Find may set the instance ID to 0xFFFF, meaning any instance of that service. The major version must match. A minor version of 0xFFFFFFFF means any minor version. Any other value is the lowest minor version that will be accepted. When several instances offer at once, an entry may carry priority and weight. The smaller priority number is chosen first. Equal priority is then split by weight.

The SD header has a reboot flag and a unicast flag. The session ID starts at 1 and increases. When the session ID wraps, or the reboot flag changes, other nodes treat the machine as restarted and must subscribe to eventgroups again.

Options

An entry points at options. The address is in the option.

OptionWhat is inside
IPv4 endpointAddress, UDP or TCP, and port. The service is reached here, and events leave from here
IPv4 multicastThe multicast address and port events are sent to
ConfigurationKey-value pairs that carry extra parameters for this service
Load balancingPriority and weight

If a subscription requires TCP, the client connects TCP first. The server may reject the subscription when that TCP connection is missing. The client checks the connection and reconnects when it has to.

Where it sits

Application layer. Method calls and events commonly use UDP in the vehicle. The overview can switch the transport to TCP. TLS can be added only on that reliable byte stream. SecOC and E2E sit on this PDU. They do not open another layer.

TCP is a byte stream. After bytes stick together, the length in the SOME/IP header cuts them apart. If the stream loses alignment, a magic cookie realigns it: the client’s message ID is 0xFFFF0000, and the server’s is 0xFFFF8000.

Packet

The header is in front of the payload. The service ID and method ID form the message ID. Length counts from the request ID to the end of the message, and does not include the message ID or the length field itself. The request ID is a client ID plus a session ID, and matches a response to one call.

Service ID16 bits. Which service
Method ID16 bits. Which method or event. High bit 1 means an event
LengthFrom the request ID to the end. The message ID and the length field are not counted
Request IDClient ID plus session ID. Matches a response to this call
VersionProtocol version is 0x01. Interface version is the service’s major version
Message type1 byte. Listed row by row in the table above
Return code1 byte. Listed row by row below. A notification is 0x00
PayloadSerialized arguments

Serialization

Basic types default to network byte order, high byte first. A struct is laid out in member order. A dynamic array or a string is preceded by a length. In classic SOME/IP the string length is 32 bits and includes the byte-order mark and the trailing NUL. The AUTOSAR serializer can also change how wide the length field is and which fields carry a length. Both sides must use the same configuration.

Segmentation on UDP

When one message does not fit in one UDP packet, SOME/IP-TP is used. The message type carries a segmentation flag, and 4 bytes follow the SOME/IP header: the offset is in units of 16 bytes, and another flag says more segments follow. The receiver reassembles by offset and hands the message to the service only when it is complete.

What it does not do

  • It does not replace a CAN signal list laid out in advance. Service, method, event, and field are a different addressing scheme.
  • SD discovers services and eventgroups. It does not carry the service’s own arguments.
  • In the vehicle it commonly uses UDP. UDP is not a reliable byte stream, so TLS does not fit on it.
  • It does not protect the link, and it does not protect the whole IP packet. The link is MACsec. IP is IPsec.
