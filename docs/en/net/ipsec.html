IPsec

IP packets are protected at the network layer. The overview draws ESP in transport mode: IPv4 stays outside, and ESP is inserted between it and UDP or TCP.

Which packets enter

Any protocol that has IP can add it: SOME/IP, DDS, DoIP, and Zenoh, on both UDP and TCP. gPTP has no IP, so it cannot. What is protected is this host to that host, not each hop of the link.

Policy selects the path first. One policy looks at the source address, the destination address, the upper protocol, and the ports, and then chooses one of three actions.

PolicyWhat it does
ProtectApply ESP with one security association
BypassLet it pass in the clear. Timing frames and discovery multicast often take this path
DiscardDo not forward it

A wrong choice either sends out plaintext that should have been protected, or the peer cannot decrypt it at all.

Security association

What actually encapsulates the packet is a security association. One association is identified by the destination address, the protocol in use (ESP here), and the SPI. The SPI is 32 bits, written in the ESP header. The receiver uses it to find the key and the algorithm. The sequence number starts at 1 and increases. The receiver uses a window against replay: a sequence number that is too old is dropped, and one already seen inside the window is dropped too. When the sequence number is about to run out, a new association is needed. The same key must not keep going with a wrapped sequence number.

How an association is negotiated is IKEv2 (RFC 7296). The overview does not draw those round trips. First there is IKE’s own association: IKE_SA_INIT exchanges key material, and IKE_AUTH checks identity. Then CREATE_CHILD_SA creates the child association that carries ESP, and it fixes the SPI, the algorithms, and the addresses and ports that association covers. Algorithms and keys are in the HSM note of AI Fortress Auto.

Where it sits

Network layer. Transport mode does not replace the outer IP header, and the EtherType stays 0x0800. Devices on the network still forward by the original addresses. The ports and the payload are inside ESP. Two ECUs protecting each other on the same link use this mode.

Tunnel mode wraps the whole original IP packet in a new IP packet. It is used when a gateway sends the packet out and the address has to change to another range. The overview does not draw the tunnel. IPv4 stays on the right of the network-layer row, and ESP is drawn under it.

Packet

ESP (RFC 4303) encrypts the transport header and the payload, plus the trailer. The integrity check covers the SPI, the sequence number, and that ciphertext. The IP address is visible outside. The port is not.

IPv4PlainStays outside
SPIPlainWhich security association
SequencePlainAnti-replay
PayloadCipherUDP or TCP
TrailerCipherPadding · pad length · next header
ICVPlainIntegrity check

The next-header field says whether the inside is UDP or TCP. After the receiver decrypts, it hands the packet to the transport layer by that field.

AH (RFC 4302) does not encrypt. It checks the integrity of the parts of the IP header that do not change while forwarding, and of the payload. Fields that change along the path, such as the hop count and the header checksum, are left out. If the address or the payload is changed, the check fails. The ports and the data stay plaintext. The overview draws ESP only, not AH.

What it does not do

  • It does not require a switch to TCP. TLS needs a reliable byte stream. IPsec does not.
  • It is not hop-by-hop MACsec. Across a switch, the outer IP header is still this one. The switch does not have to unwrap ESP.
  • It is not SecOC. SecOC is added on one application PDU and does not look at the IP address or the port.
  • gPTP does not use IP, so it is not on this page. If it is to stay out of ESP, that is a bypass in the policy, not an SPI carried by gPTP itself.
