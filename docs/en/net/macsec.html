MACsec

0x88E5 wraps an Ethernet frame hop by hop. Each hop has its own key. The VLAN tag a switch has to read stays outside the wrapper.

What one hop contains

IEEE 802.1AE. Protection on this hop is three levels deep. When the key changes, the new security association is prepared first, and then the AN switches, so the hop does not drop.

MemberWhat it is
Connectivity Association, CAThe two ends that have already agreed
Secure Channel, SCOne direction
Secure Association, SAOne key on that channel. The association number AN distinguishes them. AN is only 0 to 3

The key used on the frame is the SAK. Where the SAK comes from is MKA, the agreement inside IEEE 802.1X: the members first have a connectivity association key, the CAK, and MKA uses it to derive the current SAK on this hop and to agree the packet number at which it starts. Where the algorithms and keys are kept is in the HSM note of AI Fortress Auto. This page does not describe the derivation.

In the model a port has two sides. The uncontrolled side can still send and receive before protection is up, and MKA’s own packets use it. The controlled side admits only frames that are already wrapped in MACsec and whose check passes. A switch that only forwards transparently, and is not an endpoint of this hop, cannot unwrap the frame and cannot see the EtherType inside the VLAN.

Where it sits

Inside the data-link layer. Like 802.1Q, it is a tag inserted in the frame, not a layer above IP. With a VLAN, the order matches the overview: destination MAC, source MAC, 0x8100 and TCI, 0x88E5 and SecTAG, the original EtherType, the payload, the ICV, and the FCS. The VLAN is outside, so a switch can see the VLAN ID without decrypting, and can pick a queue by PCP.

Packet

The three type fields each keep their own value. 0x8100 is the VLAN, 0x88E5 is MACsec, and the innermost is still the original EtherType: 0x0800 for IPv4, 0x88F7 for gPTP. Without a VLAN, 0x8100 and the TCI do not appear.

The ICV sits in front of the FCS. The FCS is still Ethernet’s own CRC-32, covering the frame after it has been wrapped. The peer checks the FCS first, then the ICV. When only integrity is used and the frame is not encrypted, the payload stays plaintext and the ICV is still there.

Timing frames

gPTP frames often stay out of this secure association and use the uncontrolled side. Encryption and decryption change the residence time. If a gate was computed from the time before protection, the schedule is off. So a timing frame is often left outside 0x88E5, and its EtherType is still 0x88F7 directly. Which frames enter the association is policy for this hop, not a flag inside the gPTP header.

What it does not do

  • It is not end to end. Passing a switch means unwrap and wrap again, and the next hop is another SAK. The two ends of a byte stream are TLS. Host-to-host IP is IPsec.
  • It does not consume the original EtherType. 0x88E5 wraps the outside.
  • 0x88E3 is not MACsec. That type number does not belong to 802.1AE.
  • It does not protect a frame that did not enter this association. gPTP is often outside. Gating and residence time are still on TSN.
  • When the switch itself is not an endpoint, do not assume it will strip the wrapper and then forward. The wrapper stops between the two ports of this hop.
